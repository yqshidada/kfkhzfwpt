# 本机后端

1. 在 `server` 目录执行 `npm install`。
2. 将 `.env.example` 复制为 `.env`，按本机 MySQL/MariaDB 配置填写账号和密码，同时设置测试手机号、测试密码和 `JWT_SECRET`。
3. 执行 `npm run dev` 启动服务。首次启动会创建 `rehab_discharge` 数据库、记录表和测试登录账号。

已有旧版数据库时，启动服务也会自动补齐 `discharge_records.created_by_user_id` 字段、对应索引，以及住院号登记表，无需删除旧表或手动执行服务器迁移脚本。数据库账号需要拥有建表和 `ALTER` 权限。旧记录会保留，但由于没有创建账号信息，不会出现在任何账号的列表里；新记录会绑定当前登录账号。

默认接口地址为 `http://127.0.0.1:3000/api`。真机调试时，将 `utils/api.js` 中的主机地址改为运行后端电脑的局域网 IP，例如 `http://192.168.1.10:3000/api`。

默认测试账号为 `13800138000`，默认密码为 `Test1234`。账号必须是中国大陆 11 位手机号；密码至少 8 位，且必须同时包含字母和数字。首次启动后请在 `.env` 中修改 `TEST_LOGIN_PHONE` 和 `TEST_LOGIN_PASSWORD` 并重新启动；已创建的账号不会因修改环境变量自动修改密码。

## 扫码图片阅读

入院流程、患者报告、出院流程的二维码地址保持不变，扫码后按页显示图片，可点击放大、长按保存，并保留“下载 PDF”。原有 PDF 内容及分享有效期不变，旧报告也能使用图片阅读。

后端需要 Poppler 的 `pdfinfo` 和 `pdftoppm`。Windows 安装后将其目录加入 PATH，或在 `.env` 配置 `PDFINFO_PATH`、`PDFTOPPM_PATH` 为两个 exe 的绝对路径（推荐使用 `/`）。更改配置后重启后端。本次开发电脑已配置本地可执行文件路径。

发布到 Ubuntu 时，需要先安装 `poppler-utils`、`poppler-data`、`fonts-noto-cjk`，以支持 PDF 转换及中文字体；必须同时发布 `report-images.js`、`image-reader.js`、`image-reader-client.js`。2026-10-26 已部署到当前 Ubuntu 服务器，详见 `deploy/LINUX.md`。

首次打开某份文档时生成最长边 1800 像素的 JPEG，之后复用 `server/storage/image-cache` 中的缓存。转换逐页串行执行，避免同时启动多个转换进程；最多排队 20 份任务，每份最多 80 页。浏览器按需加载后续页，转换失败时仍可下载 PDF。图片每次请求均检查原分享是否有效，缓存不会作为公开静态目录提供。

图片是可重新生成的缓存。需要回收空间时，可在停止后端后删除 `server/storage/image-cache` 目录，再启动后端；不要删除 `server/storage/reports`，它保存原始 PDF。分享失效后，缓存即使保留也无法通过该分享访问；已下载到患者手机的文件不受撤销影响。

本机验证命令：`node server/tests/discharge-flow.cjs`。测试仅连接本地数据库，使用独立临时数据库，完成后清理，不修改现有患者数据。手机测试需与电脑处于同一 Wi-Fi，并将 `.env` 的 `SHARE_BASE_URL` 配成手机可访问的本机局域网地址。

## 预约身份证号加密

床位预约需要在本机或生产 `.env` 配置独立的 `RESERVATION_ID_KEY`（32字节随机密钥，编码为64位十六进制）。不要复用 JWT_SECRET 或在代码中写默认密钥。密钥缺失时拒绝新预约；不可解密的身份信息不会按明文回退。密钥需要安全备份，不能在已有数据后随意重新生成。详情见项目根目录 BED_RESERVATIONS.md。

## 预约图片验证码

匿名预约新增后端强制校验的6位数字字母图片验证码，模块 reservation-captcha.js，依赖 svg-captcha@1.4.0。GET /api/bed-reservations/captcha 获取图片与随机ID，POST /api/bed-reservations 顶层提交 captcha: { id, code }。300秒有效，不区分大小写，错误作废，正确绑定单个预约请求并保留同请求幂等重试。图片获取60次/IP/15分钟，原提交限流30次/IP/15分钟不变。验证码和限额是单进程内存，重启失效，多实例需要共享存储。

本地依赖已安装；新环境使用 npm ci --omit=dev --ignore-scripts。线上旧依赖树未更新时 code-only 发布会拒绝不同锁文件，需另行准备可回退的依赖发布，不能只复制JS。测试在server目录运行 npm run test:reservations。细节见项目根 BED_RESERVATIONS.md。

## 预约中重复提交限制

以规范化身份证号识别同一人。有预约中记录则返回409、code为RESERVATION_ALREADY_PENDING；已确认成功的记录不阻止新的预约。后端使用独立密钥的HMAC身份指纹和仅预约中生效的数据库唯一索引，防止不同请求并发重复入库；身份证密文存储和同请求幂等回执不变。启动自动加列/索引，保留所有历史数据；无指纹的老加密预约解密对比，极早期无身份证记录按姓名+手机号对比。指纹不在API中返回，密钥不可随意轮换。完整迁移与边界说明见根目录BED_RESERVATIONS.md。
